# Campfire

> **Campfire** — настольный цифровой игровой стол (Virtual Tabletop), ориентированный на проведение RPG-сессий в локальной сети.

---

## О проекте

Campfire создается как удобный инструмент для ведущих и игроков настольных ролевых игр.

Главная идея проекта — не заменить бумажные правила конкретной системы, а предоставить универсальную платформу, которая помогает проводить игровые сессии, управлять персонажами, боем, инвентарем и состоянием кампании.

Проект разрабатывается с учетом того, что однажды начатая кампания должна полностью восстанавливаться независимо от того, в какой момент была сохранена.

---

# Основные принципы проекта

## Кампания — главная сущность

В центре Campfire находится **не персонаж**, а **кампания**.

Кампания содержит абсолютно всё игровое состояние:

* персонажей;
* NPC;
* противников;
* сцены;
* инициативу;
* журнал;
* инвентарь;
* эффекты;
* игровые заметки;
* состояние мира.

Любое действие изменяет состояние кампании.

---

## Полное сохранение состояния

Campfire должен иметь возможность сохранить игру в любой момент.

Например:

* посреди боя;
* во время броска кубиков;
* в середине диалога;
* во время просмотра инвентаря.

После загрузки пользователь должен получить **точно такое же состояние**, какое существовало в момент сохранения.

---

## UI не хранит данные

Интерфейс отвечает только за отображение информации и взаимодействие с пользователем.

UI не содержит игровой логики.

Он показывает состояние кампании и отправляет пользовательские действия соответствующим системам.

---

## Персонаж — это данные

Объект персонажа является описанием персонажа.

Он хранит:

* характеристики;
* параметры;
* навыки;
* инвентарь;
* состояние;
* эффекты.

Игровая логика находится вне персонажа.

Например, нанесением урона, использованием предметов или обработкой эффектов занимаются отдельные игровые системы.

---

## Игровые системы независимы

Каждая подсистема отвечает только за свою область ответственности.

Примеры:

* Combat System
* Inventory System
* Dice System
* Quest System
* Scene System
* Save System

Это позволяет расширять проект без переписывания существующего кода.

---

## Единственный источник истины

Во время работы существует один объект состояния кампании.

Все игровые системы работают исключительно с ним.

Сохранение представляет собой сериализацию этого состояния.

Загрузка — восстановление этого состояния.

---

## Переиспользуемый интерфейс

Интерфейс строится из независимых компонентов.

Например:

* Button
* Panel
* Card
* Character Card
* Inventory Slot
* Stat Row

Компоненты должны быть максимально универсальными и не зависеть от конкретной игровой системы.

---

## Централизованная тема оформления

Все визуальные параметры определяются через тему проекта.

Используются единые:

* цвета;
* размеры;
* типографика;
* скругления;
* отступы;
* иконки.

Никакие визуальные значения не должны быть "зашиты" непосредственно в интерфейс.

---

# Сетевая модель

Campfire использует модель **"один ведущий — несколько игроков"**.

## Game Master

Ведущий является владельцем кампании.

Именно у него находится полное игровое состояние.

Только ведущий изменяет мир.

---

## Игроки

Игроки подключаются к кампании по локальной сети.

После подключения выбирают персонажа, которым будут управлять.

Игрок получает только ту информацию, которую ему разрешил видеть ведущий.

---

## Локальная сеть

Первая версия проекта ориентирована на использование внутри локальной сети (например, через Radmin VPN).

Это делает систему максимально простой, надежной и независимой от внешней серверной инфраструктуры.

---

# Архитектурная философия

При разработке проекта соблюдаются следующие принципы:

* простота важнее избыточной универсальности;
* архитектура важнее скорости написания кода;
* каждый модуль отвечает только за одну задачу;
* код должен быть понятен спустя несколько месяцев;
* любое решение должно быть расширяемым без переписывания проекта;
* фундамент строится один раз и максимально качественно.

---

# MVP

Первая версия Campfire должна включать:

* управление кампанией;
* карточки персонажей;
* инвентарь;
* сцены;
* журнал;
* броски кубиков;
* сохранение состояния кампании;
* подключение игроков по локальной сети.

После завершения MVP функциональность будет постепенно расширяться.
